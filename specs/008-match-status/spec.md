# Feature: แสดงสถานะการจับคู่ (Match Status)
Spec ID: SPEC-MSS-008 | Source: SRS ข้อ ... (FR-MSS) | Use case: UC-08
Owner: ทีม vista and friend | Status: Draft v3 | Updated: 2569-09-20

## Goal
นักศึกษาสามารถตรวจสอบสถานะคำขอเป็นเมทของตนเอง
และดูรายละเอียดของคำขอที่เกี่ยวข้องได้

## Scope
### In scope
- เปิดหน้าเมนูสถานะการจับคู่
- ดึงข้อมูลคำขอของนักศึกษา
- แสดงสถานะของคำขอ
- แสดงสถานะรอการตอบรับ
- แสดงสถานะจับคู่สำเร็จ
- แสดงสถานะปฏิเสธ
- ดูรายละเอียดคำขอ
- ยกเลิกคำขอที่ยังรอการตอบรับในฐานะผู้ส่ง
- รีเฟรชสถานะคำขอ

### Out of scope
- การส่งคำขอเป็นเมท (UC-06)
- การรับหรือปฏิเสธคำขอเป็นเมท (UC-07)
- การสร้างโปรไฟล์หาเมท (UC-01)
- การแก้ไขโปรไฟล์หาเมท (UC-02)
- การค้นหาเมท (UC-04)
- การติดต่อหรือแชทกับรูมเมท (UC-05)

## Constraints
- CON-MSS-01 นักศึกษาต้องเข้าสู่ระบบก่อนจึงสามารถตรวจสอบสถานะการจับคู่ได้
- CON-MSS-02 ระบบต้องดึงข้อมูลคำขอที่เกี่ยวข้องกับนักศึกษาที่เข้าสู่ระบบ
- CON-MSS-03 ระบบต้องแสดงสถานะของคำขอตามข้อมูลที่บันทึกไว้ในระบบ
- CON-MSS-04 นักศึกษาสามารถดูสถานะและรายละเอียดเฉพาะคำขอที่เกี่ยวข้องกับตนเอง
- CON-MSS-05 หากนักศึกษาไม่มีคำขอเป็นเมท ระบบต้องแสดงข้อความว่าไม่มีรายการจับคู่
- CON-MSS-06 รายการคำขอที่มีสถานะ "ยกเลิก" ต้องไม่แสดงในหน้าสถานะการจับคู่
- CON-MSS-07 การยกเลิกจากหน้านี้ทำได้เฉพาะคำขอที่ผู้ส่งส่งและยังอยู่ในสถานะ "รอการตอบรับ"
- CON-MSS-08 การยกเลิกการจับคู่ที่มีสถานะ "จับคู่สำเร็จ" ต้องดำเนินการผ่าน UC-09

## Requirements
- FR-MSS-01 ระบบต้องให้นักศึกษาสามารถเลือกเมนู "สถานะการจับคู่" ได้
- FR-MSS-02 ระบบต้องดึงข้อมูลคำขอเป็นเมทของนักศึกษา
- FR-MSS-03 ระบบต้องแสดงสถานะของคำขอเป็น "รอการตอบรับ", "จับคู่สำเร็จ" หรือ "ปฏิเสธ"
- FR-MSS-04 ระบบต้องให้นักศึกษาสามารถเลือกดูรายละเอียดของคำขอได้
- FR-MSS-05 ระบบต้องแสดงรายละเอียดของคำขอที่นักศึกษาเลือก
- FR-MSS-06 หากนักศึกษาไม่มีคำขอเป็นเมท ระบบต้องแสดงข้อความว่าไม่มีรายการจับคู่
- FR-MSS-07 ระบบต้องเรียงรายการคำขอจากรายการที่ส่งเก่าสุดไปใหม่สุด
- FR-MSS-08 เมื่อเปิดหน้าหรือกดปุ่มรีเฟรช ระบบต้องดึงสถานะล่าสุดของคำขอ
- FR-MSS-09 หากดึงข้อมูลล่าสุดไม่สำเร็จ ระบบต้องแสดงข้อผิดพลาดและคงข้อมูลเดิมที่แสดงอยู่
- FR-MSS-10 นักศึกษาผู้ส่งต้องสามารถยกเลิกคำขอที่อยู่ในสถานะ "รอการตอบรับ" ได้จากหน้านี้
- FR-MSS-11 ระบบต้องไม่แสดงรายการที่มีสถานะ "ยกเลิก"
- FR-MSS-12 ระบบต้องไม่ให้ผู้ใช้ยกเลิกการจับคู่ที่มีสถานะ "จับคู่สำเร็จ" จากหน้านี้

## Quality Requirements
- NFR-MSS-01 ระบบต้องอนุญาตให้เฉพาะนักศึกษาที่เข้าสู่ระบบแล้วสามารถตรวจสอบสถานะการจับคู่ได้
- NFR-MSS-02 ระบบต้องแสดงสถานะการจับคู่ตามข้อมูลล่าสุดที่บันทึกไว้ในระบบ
- NFR-MSS-03 ในการทดสอบกับนักศึกษาที่ไม่เคยใช้หน้าสถานะ 5 คน อย่างน้อย 80% ต้องตรวจสอบสถานะและเปิดรายละเอียดสำเร็จโดยไม่รับคำแนะนำ

## Acceptance Criteria
- [ ] AC-MSS-01 (FR-MSS-01)
      Given นักศึกษาเข้าสู่ระบบแล้ว
      When นักศึกษาเลือกเมนู "สถานะการจับคู่"
      Then ระบบเปิดหน้าสถานะการจับคู่

- [ ] AC-MSS-02 (FR-MSS-02, FR-MSS-03, FR-MSS-11)
      Given นักศึกษาอยู่ในหน้าสถานะการจับคู่
      When ระบบดึงข้อมูลคำขอของนักศึกษา
      Then ระบบแสดงเฉพาะรายการที่มีสถานะ "รอการตอบรับ", "จับคู่สำเร็จ" หรือ "ปฏิเสธ" พร้อมสถานะปัจจุบัน

- [ ] AC-MSS-02A (FR-MSS-07)
      Given นักศึกษามีคำขอเป็นเมทหลายรายการ
      When ระบบแสดงรายการคำขอ
      Then ระบบเรียงรายการจากคำขอที่ส่งเก่าสุดไปใหม่สุด

- [ ] AC-MSS-03 (FR-MSS-04, FR-MSS-05)
      Given ระบบแสดงรายการคำขอเป็นเมท
      When นักศึกษาเลือกดูรายละเอียดคำขอ
      Then ระบบแสดงชื่อและรูปโปรไฟล์ของคู่สนทนา สถานะคำขอ วันที่ส่ง วันที่อัปเดต และข้อความประกอบถ้ามี

- [ ] AC-MSS-04 (FR-MSS-06)
      Given นักศึกษาไม่มีคำขอเป็นเมท
      When นักศึกษาเปิดหน้าสถานะการจับคู่
      Then ระบบแสดงข้อความว่าไม่มีรายการจับคู่

- [ ] AC-MSS-05 (NFR-MSS-01)
      Given นักศึกษายังไม่ได้เข้าสู่ระบบ
      When นักศึกษาพยายามเข้าสู่หน้าสถานะการจับคู่
      Then ระบบปฏิเสธการเข้าใช้งานและให้นักศึกษาเข้าสู่ระบบก่อน

- [ ] AC-MSS-06 (FR-MSS-08, FR-MSS-09)
      Given นักศึกษาอยู่ในหน้าสถานะการจับคู่และมีข้อมูลเดิมแสดงอยู่
      When นักศึกษาเปิดหน้าหรือกดปุ่มรีเฟรชแล้วการดึงข้อมูลล้มเหลว
      Then ระบบแสดงข้อผิดพลาดและคงข้อมูลเดิมไว้

- [ ] AC-MSS-07 (FR-MSS-10)
      Given นักศึกษาเป็นผู้ส่งคำขอที่อยู่ในสถานะ "รอการตอบรับ"
      When นักศึกษาเลือกยกเลิกคำขอจากหน้าสถานะการจับคู่
      Then ระบบดำเนินการยกเลิกคำขอผ่านกระบวนการที่กำหนดและไม่แสดงคำขอนั้นเป็นสถานะที่ใช้งานได้ในหน้านี้

- [ ] AC-MSS-07A (CON-MSS-07, FR-MSS-12)
      Given นักศึกษามีรายการที่มีสถานะ "จับคู่สำเร็จ"
      When นักศึกษาเลือกการดำเนินการจากหน้าสถานะการจับคู่
      Then ระบบไม่แสดงตัวเลือกยกเลิกการจับคู่และแจ้งให้ใช้กระบวนการ UC-09

- [ ] AC-MSS-08 (NFR-MSS-03)
      Given นักศึกษาที่ไม่เคยใช้หน้าสถานะจำนวน 5 คน
      When นักศึกษาแต่ละคนตรวจสอบสถานะและเปิดรายละเอียดคำขอ
      Then อย่างน้อย 4 คนดำเนินการสำเร็จโดยไม่รับคำแนะนำ

## Assumptions & Open Questions
- ASM-MSS-01 นักศึกษาต้องเข้าสู่ระบบก่อนใช้งานฟังก์ชันแสดงสถานะการจับคู่
- ASM-MSS-02 ระบบสามารถดึงข้อมูลคำขอเป็นเมทของนักศึกษาได้
- ASM-MSS-03 สถานะคำขอมีอย่างน้อย 3 สถานะ ได้แก่ รอการตอบรับ, จับคู่สำเร็จ และปฏิเสธ
- ASM-MSS-04 นักศึกษาสามารถดูรายละเอียดของคำขอที่เกี่ยวข้องกับตนเองได้

- Q-MSS-01 หากมีหลายคำขอ ระบบจะแสดงเรียงตามอะไร?
-> ตอบแล้ว: เรียงจากคำขอที่ส่งเก่าสุดไปใหม่สุด
- Q-MSS-02 รายละเอียดของคำขอจะแสดงข้อมูลอะไรบ้าง?
-> ตอบแล้ว: ชื่อและรูปโปรไฟล์ของคู่สนทนา สถานะคำขอ วันที่ส่ง วันที่อัปเดต และข้อความประกอบถ้ามี
- Q-MSS-03 เมื่อจับคู่สำเร็จแล้ว คำขอจะแสดงอยู่ในหน้านี้ต่อไปหรือไม่?
-> ตอบแล้ว: แสดงต่อไปจนกว่าจะยกเลิกการจับคู่
- Q-MSS-04 นักศึกษาสามารถยกเลิกคำขอที่อยู่ในสถานะ "รอการตอบรับ" จากหน้านี้ได้หรือไม่?
-> ตอบแล้ว: ผู้ส่งยกเลิกได้จากหน้านี้
- Q-MSS-05 รายการที่มีสถานะ "ยกเลิก" ควรแสดงในหน้านี้หรือไม่?
-> ตอบแล้ว: ไม่แสดงรายการที่มีสถานะ "ยกเลิก"
- Q-MSS-06 การยกเลิกการจับคู่สำเร็จทำจากหน้านี้ได้หรือไม่?
-> ตอบแล้ว: ไม่ได้ หน้านี้ยกเลิกได้เฉพาะคำขอที่รอการตอบรับ ส่วนการยกเลิกการจับคู่สำเร็จใช้ UC-09
- Q-MSS-07 ระบบควรรีเฟรชสถานะอย่างไร?
-> ตอบแล้ว: ดึงข้อมูลเมื่อเปิดหน้าและเมื่อผู้ใช้กดปุ่มรีเฟรชเอง
