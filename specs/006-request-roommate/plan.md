# Plan v1: Align request roommate specification

## Problem and approach

ปรับ [spec.md](spec.md) จาก Draft v2 เป็น Draft v3 ให้ชัดเจนเรื่องข้อความประกอบ การตรวจสอบสถานะแบบ atomic การส่งคำขอซ้ำหลังการจับคู่ และการ retry แจ้งเตือน พร้อมปรับ acceptance criteria และ traceability ให้ทดสอบได้

## Scope decisions

- ข้อความประกอบคำขอเป็นข้อมูลเสริม ความยาวไม่เกิน 500 ตัวอักษร
- ระบบตรวจสอบสถานะผู้รับและคำขอเดิมแบบ atomic อีกครั้งก่อนบันทึกคำขอ
- หากมีการจับคู่สำเร็จระหว่างผู้ส่งกับผู้รับอยู่ จะส่งคำขอใหม่ไม่ได้จนกว่าการจับคู่เดิมจะถูกยกเลิก
- หากแจ้งเตือนล้มเหลว ระบบลองส่งซ้ำอัตโนมัติ 3 ครั้ง แล้วคงคำขอเป็น `รอการตอบรับ`

## Tasks

1. ปรับข้อมูลคำขอและ validation ของข้อความประกอบ
2. ระบุการตรวจสอบสถานะ/คำขอซ้ำแบบ atomic ก่อนบันทึก
3. ระบุข้อจำกัดการส่งคำขอเมื่อมีการจับคู่สำเร็จ และการส่งใหม่หลังยกเลิก
4. ระบุ retry และ failure handling ของการแจ้งเตือน
5. ปรับ requirements, acceptance criteria, assumptions และ traceability ให้สอดคล้องกับ v3
6. ตรวจ diff และ markdown consistency แล้ว commit เป็น `Draft v3`

## Notes and considerations

- ต้องไม่สร้างคำขอซ้ำจาก race condition ระหว่างการตรวจสอบกับการบันทึก
- ต้องไม่ทำให้การปิดสถานะหรือการตอบรับคำขอในฟีเจอร์อื่นขัดกับกติกาของคำขอ
- ต้องคงคำขอที่บันทึกสำเร็จไว้ แม้การแจ้งเตือนจะล้มเหลว
- ต้องไม่แก้ไฟล์ attachment แบบ read-only และต้องคงการเปลี่ยนแปลงที่ไม่เกี่ยวข้องใน working tree
