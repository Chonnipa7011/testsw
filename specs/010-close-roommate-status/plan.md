# Plan v1: Align close roommate status specification

## Problem and approach

ปรับ [spec.md](spec.md) จาก Draft v2 เป็น Draft v3 ให้ชัดเจนเรื่อง atomic status closing, การปฏิเสธคำขอที่รอ การแจ้งเตือน และพฤติกรรมของแชทเดิม

## Scope decisions

- การปิดสถานะและการปฏิเสธคำขอที่รอทั้งหมดต้องทำเป็น atomic operation เดียว
- หาก operation ล้มเหลว ระบบต้องไม่บันทึกการเปลี่ยนแปลงบางส่วนและคงสถานะเดิมไว้
- การแจ้งเตือนผู้ส่งคำขอที่ถูกปฏิเสธลองซ้ำอัตโนมัติ 3 ครั้ง และคงสถานะคำขอเป็น `ปฏิเสธ` หากยังล้มเหลว
- การปิดสถานะไม่กระทบการจับคู่สำเร็จ
- แชทเดิมยังอ่านประวัติได้ แต่ส่งข้อความใหม่ไม่ได้เมื่อปิดสถานะ
- เมื่อเปิดสถานะกลับสำเร็จ โปรไฟล์กลับมาแสดงในผลการค้นหาและรับคำขอใหม่ได้ทันที

## Tasks

1. เพิ่ม constraints และ requirements สำหรับ atomic status closing และการปฏิเสธคำขอที่รอ
2. ระบุ retry และ failure handling ของการแจ้งเตือนผู้ส่งคำขอ
3. ระบุผลต่อการจับคู่สำเร็จ การค้นหา การรับคำขอ และแชทเดิม
4. ปรับ acceptance criteria, assumptions, open questions และ traceability ให้สอดคล้องกับ Draft v3
5. ตรวจ diff และ Markdown consistency แล้ว commit เป็น `Draft v3`

## Notes and considerations

- ต้องไม่เปลี่ยนสถานะโปรไฟล์โดยที่คำขอรอไม่ได้ถูกจัดการใน operation เดียวกัน
- ต้องคงสถานะคำขอ `ปฏิเสธ` แม้การแจ้งเตือนจะล้มเหลวหลัง retry ครบ 3 ครั้ง
- ต้องไม่ทำให้การจับคู่สำเร็จถูกปฏิเสธหรือยกเลิกโดยอัตโนมัติ
- ต้องให้พฤติกรรมแชท read-only สอดคล้องกับ [spec.md](../005-chat-roommate/spec.md)
- ต้องไม่แก้ไฟล์ attachment แบบ read-only และต้องคงการเปลี่ยนแปลงที่ไม่เกี่ยวข้องใน working tree
