# Plan v1: Align cancel match specification

## Problem and approach

ปรับ [spec.md](spec.md) จาก Draft v2 เป็น Draft v3 ให้ชัดเจนเรื่อง atomic cancellation, การแจ้งเตือน การค้นหาใหม่หลังยกเลิก และพฤติกรรมของแชทเดิม

## Scope decisions

- การยกเลิกต้องตรวจสอบสมาชิกและสถานะการจับคู่แบบ atomic ก่อนบันทึก
- หากแจ้งเตือนล้มเหลว ระบบลองส่งซ้ำอัตโนมัติ 3 ครั้ง แล้วคงสถานะ `ยกเลิก`
- หลังยกเลิก โปรไฟล์กลับมาแสดงในผลค้นหาได้เมื่อเจ้าของเปิดสถานะ และส่งคำขอ/จับคู่ใหม่ได้ตามกติกา
- แชทเดิมยังอ่านประวัติได้ แต่ส่งข้อความใหม่ไม่ได้

## Tasks

1. ระบุ atomic validation และการเปลี่ยนสถานะการจับคู่
2. ปรับ failure handling และ retry ของการแจ้งเตือน
3. ระบุผลต่อการค้นหา การส่งคำขอใหม่ และแชทเดิมหลังยกเลิก
4. ปรับ requirements, acceptance criteria, assumptions และ traceability ให้สอดคล้องกับ v3
5. ตรวจ diff และ markdown consistency แล้ว commit เป็น `Draft v3`

## Notes and considerations

- ต้องไม่บันทึกการยกเลิกของผู้ที่ไม่ใช่สมาชิกหรือการจับคู่ที่ไม่อยู่ในสถานะสำเร็จ
- ต้องคงสถานะ `ยกเลิก` แม้การแจ้งเตือนจะล้มเหลว
- ต้องไม่ทำให้กติกาแชท read-only หลังปิดสถานะขัดกับสเปกแชท
- ต้องไม่แก้ไฟล์ attachment แบบ read-only และต้องคงการเปลี่ยนแปลงที่ไม่เกี่ยวข้องใน working tree
