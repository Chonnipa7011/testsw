# Feature: ระบุความต้องการหาเมท (Roommate Preference)
Spec ID: SPEC-RPS-003 | Source: SRS ข้อ ... (FR-RPS) | Use case: UC-03
Owner: ทีม vista and friend | Status: Draft v3 | Updated: 2569-09-20

## Goal
นักศึกษาสามารถระบุลักษณะหรือความต้องการของเมทที่ต้องการ
เพื่อให้ระบบสามารถนำข้อมูลความต้องการไปใช้ในการค้นหาและจับคู่รูมเมทได้

## Scope
### In scope
- เปิดหน้าเมนูความต้องการหาเมท
- แสดงตัวเลือกความต้องการ
- เลือกหรือกรอกข้อมูลความต้องการ
- ตรวจสอบข้อมูลที่จำเป็น
- บันทึกข้อมูลความต้องการ
- แสดงข้อมูลความต้องการที่บันทึกแล้ว

### Out of scope
- การสร้างโปรไฟล์หาเมท (UC-01)
- การแก้ไขโปรไฟล์หาเมท (UC-02)
- การค้นหาหรือจับคู่รูมเมทโดยตรง ยกเว้นการจัดเก็บข้อมูลความต้องการให้พร้อมใช้งานเป็นเงื่อนไขค้นหาและจับคู่
- การติดต่อหรือแชทกับรูมเมท

## Constraints
- CON-RPS-01 นักศึกษาต้องเข้าสู่ระบบก่อนจึงสามารถระบุความต้องการหาเมทได้
- CON-RPS-02 นักศึกษาต้องมีโปรไฟล์หาเมทก่อนจึงสามารถระบุความต้องการได้
- CON-RPS-03 ข้อมูลความต้องการที่จำเป็นต้องถูกระบุก่อนจึงสามารถบันทึกได้
- CON-RPS-04 หากไม่ได้ระบุข้อมูลที่จำเป็น ระบบต้องไม่บันทึกข้อมูลความต้องการ
- CON-RPS-05 ข้อมูลความต้องการที่บันทึกแล้วต้องแก้ไขได้โดยเจ้าของโปรไฟล์เท่านั้น
- CON-RPS-06 การเลือกจำนวนคนในห้องต้องสอดคล้องกับรูปแบบห้องที่เลือก

## Requirements
- FR-RPS-01 ระบบต้องให้นักศึกษาสามารถเลือกเมนู "ความต้องการหาเมท" ได้
- FR-RPS-02 ระบบต้องแสดงตัวเลือกความต้องการสำหรับการหาเมท
- FR-RPS-03 ระบบต้องให้นักศึกษาสามารถเลือกข้อมูลความต้องการจากตัวเลือกที่กำหนดและกรอกข้อมูลเพิ่มเติมได้
- FR-RPS-04 ระบบต้องตรวจสอบว่าข้อมูลความต้องการที่จำเป็นถูกระบุครบก่อนบันทึก
- FR-RPS-05 หากไม่ได้ระบุข้อมูลที่จำเป็น ระบบต้องแจ้งเตือนให้นักศึกษากรอกข้อมูล
- FR-RPS-06 เมื่อข้อมูลความต้องการผ่านการตรวจสอบ ระบบต้องบันทึกข้อมูลความต้องการของนักศึกษา
- FR-RPS-07 หลังจากบันทึกข้อมูลสำเร็จ ระบบต้องแสดงข้อมูลความต้องการที่บันทึกแล้ว
- FR-RPS-08 ระบบต้องจัดเก็บข้อมูลความต้องการในรูปแบบที่สามารถนำไปใช้ในการค้นหาและจับคู่รูมเมทได้
- FR-RPS-09 ระบบต้องตรวจสอบรูปแบบห้อง จำนวนคนในห้อง และความยาวของข้อมูลเพิ่มเติมตาม validation rules ก่อนบันทึก

### Preference fields and validation rules
- หัวข้อความต้องการประกอบด้วยจำนวนคนในห้อง รูปแบบห้อง พฤติกรรมการนอน ความสะอาด เวลาเข้านอน และข้อมูลเพิ่มเติม
- จำนวนคนในห้องและรูปแบบห้องเป็นข้อมูลที่จำเป็น และหมายถึงห้องที่ผู้ใช้ต้องการ โดยห้องแอร์เลือกได้ 1–4 คน และห้องพัดลมเลือกได้ 1–3 คน
- พฤติกรรมการนอนเป็นข้อมูลเสริม เลือกได้จาก กรน, กัดฟัน, นอนดิ้น หรือ ไม่มีพฤติกรรมดังกล่าว
- ความสะอาดเป็นข้อมูลเสริม เลือกได้จาก สะอาดมาก, ปานกลาง หรือ ยืดหยุ่น
- เวลาเข้านอนเป็นข้อมูลเสริม เลือกได้จาก ก่อน 22:00, 22:00–00:00, หลัง 00:00 หรือ ยืดหยุ่น
- ข้อมูลเพิ่มเติมเป็นข้อมูลเสริมแบบข้อความอิสระ ความยาวไม่เกิน 500 ตัวอักษร และหากเริ่มกรอกต้องไม่เป็นข้อความว่าง
- ไม่รวมความต้องการด้านการสูบบุหรี่ การเลี้ยงสัตว์ หรืองบประมาณ
- ข้อมูลความต้องการที่บันทึกสำเร็จต้องนำไปใช้เป็นเงื่อนไขในการค้นหาและจับคู่ได้ทันที
- หากบันทึกไม่สำเร็จ ระบบต้องไม่บันทึกข้อมูลบางส่วนและต้องคงข้อมูลเดิมไว้

## Quality Requirements
- NFR-RPS-01 ระบบต้องอนุญาตให้เฉพาะนักศึกษาที่เข้าสู่ระบบและเป็นเจ้าของโปรไฟล์สามารถจัดการข้อมูลความต้องการของตนเองได้
- NFR-RPS-02 ระบบต้องไม่บันทึกข้อมูลความต้องการ หากข้อมูลที่จำเป็นยังไม่ครบ
- NFR-RPS-03 ในการทดสอบกับนักศึกษาที่ไม่เคยใช้ฟังก์ชันนี้ 5 คน อย่างน้อย 80% ต้องบันทึกความต้องการสำเร็จโดยไม่รับคำแนะนำ

## Acceptance Criteria
- [ ] AC-RPS-01 (FR-RPS-01, FR-RPS-02)
      Given นักศึกษาเข้าสู่ระบบแล้วและมีโปรไฟล์หาเมท
      When นักศึกษาเลือกเมนู "ความต้องการหาเมท"
      Then ระบบแสดงตัวเลือกความต้องการ

- [ ] AC-RPS-02 (FR-RPS-03)
      Given นักศึกษาอยู่ในหน้าความต้องการหาเมท
      When นักศึกษาเลือกหรือกรอกข้อมูลความต้องการ
      Then ระบบรับข้อมูลความต้องการของนักศึกษา

- [ ] AC-RPS-02A (CON-RPS-03)
      Given นักศึกษาอยู่ในหน้าความต้องการหาเมท
      When นักศึกษาระบุจำนวนคนในห้องและรูปแบบห้อง
      Then ระบบยอมรับเฉพาะจำนวนคน 1–4 คนสำหรับห้องแอร์ หรือ 1–3 คนสำหรับห้องพัดลม

- [ ] AC-RPS-02B (CON-RPS-06, FR-RPS-09)
      Given นักศึกษาอยู่ในหน้าความต้องการหาเมท
      When นักศึกษาเลือกจำนวนคนที่ไม่สอดคล้องกับรูปแบบห้อง
      Then ระบบแจ้งข้อผิดพลาดและไม่อนุญาตให้บันทึกข้อมูล

- [ ] AC-RPS-02C (FR-RPS-03, FR-RPS-09)
      Given นักศึกษาอยู่ในหน้าความต้องการหาเมท
      When นักศึกษากรอกข้อมูลเพิ่มเติมยาวเกิน 500 ตัวอักษร หรือกรอกเป็นช่องว่าง
      Then ระบบแจ้งข้อผิดพลาดและไม่อนุญาตให้บันทึกข้อมูล

- [ ] AC-RPS-03 (FR-RPS-04, FR-RPS-05)
      Given นักศึกษาอยู่ในหน้าความต้องการหาเมท
      When นักศึกษากดยืนยันโดยไม่ได้ระบุข้อมูลที่จำเป็น
      Then ระบบแจ้งเตือนให้นักศึกษากรอกข้อมูลที่จำเป็นและไม่บันทึกข้อมูลความต้องการ

- [ ] AC-RPS-04 (FR-RPS-04, FR-RPS-06, FR-RPS-07)
      Given นักศึกษาระบุข้อมูลความต้องการที่จำเป็นครบแล้ว
      When นักศึกษากดยืนยัน
      Then ระบบบันทึกข้อมูลความต้องการและแสดงข้อมูลที่บันทึกแล้ว

- [ ] AC-RPS-04A (FR-RPS-06, CON-RPS-05)
      Given นักศึกษามีข้อมูลความต้องการที่บันทึกไว้
      When นักศึกษาแก้ไขข้อมูลความต้องการของตนเองและยืนยัน
      Then ระบบตรวจสอบและบันทึกข้อมูลใหม่

- [ ] AC-RPS-04B (FR-RPS-06, FR-RPS-09)
      Given นักศึกษากรอกข้อมูลความต้องการครบถ้วน
      When การบันทึกข้อมูลล้มเหลว
      Then ระบบคงข้อมูลเดิม ไม่บันทึกข้อมูลบางส่วน แจ้งข้อผิดพลาด และให้นักศึกษาลองใหม่ได้

- [ ] AC-RPS-05 (FR-RPS-08)
      Given นักศึกษาบันทึกข้อมูลความต้องการสำเร็จ
      When ระบบนำข้อมูลความต้องการไปใช้
      Then ข้อมูลความต้องการสามารถนำไปใช้ในการค้นหาและจับคู่รูมเมทได้ทันที

- [ ] AC-RPS-06 (NFR-RPS-01)
      Given นักศึกษาเข้าสู่ระบบแล้ว
      When นักศึกษาพยายามจัดการข้อมูลความต้องการของนักศึกษาคนอื่น
      Then ระบบปฏิเสธการเข้าถึงข้อมูลดังกล่าว

- [ ] AC-RPS-07 (CON-RPS-02)
      Given นักศึกษาเข้าสู่ระบบแล้วแต่ยังไม่มีโปรไฟล์หาเมท
      When นักศึกษาเลือกเมนู "ความต้องการหาเมท"
      Then ระบบแจ้งว่ายังไม่มีโปรไฟล์และพาไปยังหน้าสร้างโปรไฟล์หาเมท

- [ ] AC-RPS-08 (NFR-RPS-03)
      Given นักศึกษาที่ไม่เคยใช้ฟังก์ชันนี้จำนวน 5 คน
      When นักศึกษาแต่ละคนระบุและบันทึกความต้องการหาเมท
      Then อย่างน้อย 4 คนบันทึกสำเร็จโดยไม่รับคำแนะนำ

## Assumptions & Open Questions
- ASM-RPS-01 นักศึกษาต้องเข้าสู่ระบบก่อนใช้งานฟังก์ชันระบุความต้องการหาเมท
- ASM-RPS-02 นักศึกษาต้องมีโปรไฟล์หาเมทก่อนระบุความต้องการ
- ASM-RPS-03 ระบบมีตัวเลือกความต้องการที่กำหนดไว้สำหรับให้นักศึกษาเลือก
- ASM-RPS-04 ข้อมูลความต้องการที่บันทึกแล้วสามารถนำไปใช้ในกระบวนการค้นหาและจับคู่รูมเมทได้

- Q-RPS-01 ความต้องการหาเมทมีหัวข้อหรือข้อมูลอะไรบ้าง?
-> ตอบแล้ว: จำนวนคนในห้อง รูปแบบห้อง พฤติกรรมการนอน ความสะอาด เวลาเข้านอน และข้อมูลเพิ่มเติม
- Q-RPS-02 ข้อมูลใดบ้างที่เป็นข้อมูลจำเป็น?
-> ตอบแล้ว: จำนวนคนในห้องและรูปแบบห้องเป็น required; หัวข้ออื่นเป็น optional
- Q-RPS-03 นักศึกษาสามารถกรอกความต้องการเพิ่มเติมนอกเหนือจากตัวเลือกที่ระบบกำหนดหรือไม่?
-> ตอบแล้ว: กรอกข้อมูลเพิ่มเติมแบบข้อความอิสระได้ ความยาวไม่เกิน 500 ตัวอักษร และหากเริ่มกรอกต้องไม่เป็นข้อความว่าง
- Q-RPS-04 จำนวนคนในห้องและรูปแบบห้องในความต้องการหาเมทหมายถึงอะไร และใช้ validation ใด?
-> ตอบแล้ว: หมายถึงห้องที่ผู้ใช้ต้องการ และใช้ช่วงค่าเดียวกับโปรไฟล์ คือห้องแอร์ 1–4 คน และห้องพัดลม 1–3 คน
