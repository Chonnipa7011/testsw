# Plan v1: Align respond roommate request specification

## Problem and approach

ปรับ [spec.md](spec.md) จาก Draft v2 เป็น Draft v3 ให้ชัดเจนเรื่องการเปลี่ยนสถานะคำขอ การจับคู่สำเร็จ การเปลี่ยนผลภายหลัง atomic transition การแจ้งเตือน และความสอดคล้องกับการยกเลิกการจับคู่

## Scope decisions

- การเปลี่ยนจาก `จับคู่สำเร็จ` เป็น `ปฏิเสธ` ถือเป็นการยกเลิกการจับคู่และใช้กฎเดียวกับ UC-09
- การตอบรับหรือเปลี่ยนผลการตอบรับต้องตรวจสอบและเปลี่ยนสถานะแบบ atomic
- หากแจ้งเตือนผลการตอบรับล้มเหลว ระบบลองส่งซ้ำอัตโนมัติ 3 ครั้ง แล้วคงสถานะใหม่
- หลังผู้รับปฏิเสธคำขอที่ยังรอการตอบรับ ผู้ส่งส่งคำขอใหม่ให้ผู้รับคนเดิมได้ทันที

## Tasks

1. ปรับกติกาการตอบรับ/ปฏิเสธและการเปลี่ยนผลภายหลัง
2. ระบุ atomic transition และการจัดการคำขออื่นเมื่อจับคู่สำเร็จ
3. เชื่อมการเปลี่ยนจากจับคู่สำเร็จเป็นปฏิเสธกับ UC-09
4. ระบุ retry และ failure handling ของการแจ้งเตือนผลลัพธ์
5. ปรับ requirements, acceptance criteria, assumptions และ traceability ให้สอดคล้องกับ v3
6. ตรวจ diff และ markdown consistency แล้ว commit เป็น `Draft v3`

## Notes and considerations

- ต้องไม่ให้การตอบรับพร้อมกันทำให้เกิดการจับคู่สำเร็จมากกว่าหนึ่งรายการสำหรับผู้รับ
- ต้องไม่ให้การเปลี่ยนจากจับคู่สำเร็จเป็นปฏิเสธขัดกับสถานะการยกเลิกใน UC-09
- ต้องคงสถานะใหม่ไว้แม้การแจ้งเตือนจะล้มเหลว
- ต้องไม่แก้ไฟล์ attachment แบบ read-only และต้องคงการเปลี่ยนแปลงที่ไม่เกี่ยวข้องใน working tree
